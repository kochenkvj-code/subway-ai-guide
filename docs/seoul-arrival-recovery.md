# Seoul / City Hall arrival display recovery

Investigation observed that the station-arrival feed could contain no usable upbound ETA while the line-position feed contained current upbound trains at Seoul and Namyeong. Later station snapshots recovered the same train identifiers. Seoul is queried once as `서울`; the response matcher accepts both 서울 and 서울역. No second alias query is introduced.

V2 now distinguishes usable ETA/arrival states from fresh location-only evidence. Unknown ETAs are never inferred from distances or schedules. After the existing 60-second arrival-state window expires, a location may remain visible as **location information only**, up to the existing 3-minute freshness limit. Legacy calls retain their previous behavior. The UI uses localized location-only/time-unavailable labels and the relevant source timestamp rather than continuing to claim that a train has arrived.

For the verified line-1 corridor at Seoul (0150) and City Hall (0151), the server also requests line-1 position evidence in parallel, using the already configured SEOUL_SUBWAY_POSITION_API_KEY. The line-level cache and pending request coalesce for 15 seconds; failures do not break genuine arrival responses. Only positions received within 90 seconds, on the same line and direction, on a unique directed path up to three stops behind the station are admitted. Supplemental candidates must have a recognized onward destination path. Trains already beyond/departed the target are removed only when the independent position is at least as new as the arrival record. Matching uses original train identifiers; no ETA or physical movement between reports is invented. More complex lines are not given this topology fallback without separate validation.

**Train numbers remain exactly as the provider supplied them.** The proposed 3xxx→2xxx display conversion was removed before commit/deployment after the user's correction. There is no displayTrainNo remapping, and investigation of line-2 numbering is intentionally stopped. Regression tests ensure raw 3266 remains 3266 in API and UI.

Validation: arrivals unit/API tests cover supplementary positions, independent caching, no invented ETAs, failure isolation, unchanged raw train identifiers, stale-state expiry and legacy behavior. `node tests/seoul-arrival-recovery-ui.cjs` checks all four languages and the unchanged raw number; `npm run test:arrivals-ui` keeps the existing multi-station browser flow passing. Test APIs/positions are fixtures; no production analytics records are written.
