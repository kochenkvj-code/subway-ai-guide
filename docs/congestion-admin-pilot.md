# Administrator congestion pilot
- Source: https://data.seoul.go.kr/dataList/OA-12928/S/1/datasetView.do, Open API subwConfusion (user-provided official screenshots). Seoul Metro's 1–8 line half-hour averages, not measured train-specific congestion.
- Key: SEOUL_CONGESTION_API_KEY, server only, official documented HTTP endpoint. No key or raw URL is logged or returned. Admin API verifies existing signed staff cookie, private no-store response. Existing source uses HTTP; transport is not encrypted.
- Fetch 1–1000 and subsequent pages, daily Next Data Cache revalidation, no changed DB or cron. Client selects current KST time, retries after failure; no request in passenger mode. Missing data, unknown direction, conflicting duplicates, zero/no service, or unsupported line show existing uncolored heading, no fabricated values. Line 6 upstream loop hints do not imply platform congestion. Public holidays use calendar day category pending verification; midnight slots only shown if explicit matching field exists.
- A design: header only, symmetric arrows/station/people, home text with very crowded split, details percentage, detail click explains statistics and source. Original position data/refresh/grouping untouched. Percent bands 80/130/150 are agreed UI labels, not official safety guidance.
- API schema based on official screenshots; real-key response and exact source vintage not yet verified from development environment (DNS unavailable). Tests use simulated pages. Check authenticated /api/v2/congestion?station=0154 and actual layouts/time slots before opening to passengers.
